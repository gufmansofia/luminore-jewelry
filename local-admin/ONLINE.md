# Online admin rollout

The separate online admin is published at https://admin.luminorejewelry.com/admin, with the original https://luminore-jewelry-admin.sgufman06.chatgpt.site/admin address also available. The online version uses owner-requested email-only entry, an invited-email allowlist, D1 records and R2 uploads. There is no password, OTP, email delivery or external sign-in provider. The owner explicitly accepted that anyone who knows an allowed email can enter as that member. Random HttpOnly cookie sessions are stored as hashes, checked against current membership, and invalidated on logout or revocation. The loopback-only Bun prototype remains separate and must never be exposed to the internet.

The website can consume only approved snapshots during its build by setting `ADMIN_CATALOGUE_URL=https://luminore-jewelry-admin.sgufman06.chatgpt.site/catalogue.json`. Leave the setting unset until catalogue migration, the Google Sheets bridge and a production deploy hook have been verified. Without it, the existing curated stock stays unchanged.

`build.ts` refreshes the snapshot before loading SEO modules or bundling the client. `mergeAdminProducts` preserves existing product IDs and SKUs, updates translated website fields and adds new published products. Failed downloads, empty catalogues or conflicting identity stop the new build, retaining the previous deployment. The build emits `.well-known/luminore-catalogue.json` so the admin can verify the actual published release instead of claiming completion merely after triggering a hook.

The Google stock spreadsheet is `1QSFCK1olOhxoxPO004xyABNHbVxB2xD8P_FexZikEJ4`, tab `Stock`, headers on row 6, data from row 7, columns A:O. Descriptions and translations are mirrored separately to `Website text!A:F` using the same permanent SKU. The Apps Script bridge extends the existing native tables so new rows remain inside their filters and dropdown columns. Drafts must never be sent there. A copied workbook must be used for the end-to-end test. Native tools in a chat do not constitute permanent credentials for the hosted application.

The initial catalogue transfer completed: all 110 records matched the local source, including published snapshots, pending edits and trash. Both owner addresses remain configured; live email-only entry and catalogue access have been verified. Subsequent team edits remain in the hosted database. Current rollout limits are permanent Google Sheets authorization and the complete live publication flow. The authorized Vercel main-branch hook has been created and stored as a Sites runtime secret; it has not been triggered. Publication is blocked in the online API until the external connections exist. The website integration is prepared but not activated on the official domain.

Publication additionally requires `PUBLICATION_ENABLED=true` after verification. It remains unset during rollout. An interrupted catalogue import can resume from the same transfer file after reloading; existing team edits are preserved. Publication delivery uses a bounded lease to prevent overlapping retries and resumes without duplicating the permanent SKU or a synchronized sheet row.

A separate test workbook and Apps Script project have been staged. The Google deployment is waiting for its authorization dialog; no script writes have been made to the working spreadsheet.

Google Sheets API v4 has been staged in the Apps Script service picker. Its displayed API terms and the Google authorization must still be confirmed by the owner before the live test. All independent code checks pass; no end-to-end live delivery is claimed before that test.

Multiple catalogue owners are supported by the primary `ADMIN_OWNER_EMAIL` plus optional comma-separated `ADMIN_OWNER_EMAILS` runtime secrets. Owners enter their configured email; staff enter an email previously added by an owner. These settings bootstrap owners once; after bootstrap, database membership is authoritative. Any owner can assign all four roles, appoint other owners, change their rights or revoke their access. The last active owner is protected. Emails are not hard-coded into website source.

The custom hostname `admin.luminorejewelry.com` is active with HTTPS. In Websupport, its previous A record (37.9.175.12, TTL 600) was replaced with CNAME `custom-domains.chatgpt.site.` and the two provider-supplied verification TXT records were added. The before/after DNS comparison confirmed no other records changed. Sites reports both hostname and SSL active, and live email entry and catalogue access were verified on this hostname. The prepared Sheets bridge photo-origin allowlist now includes this verified custom hostname for newly uploaded images; the bridge is still inactive.

The product editor's single "Описание и переводы" section now offers English, Русский and Українська, each editing its own existing name and description fields. English persistence and the other languages were checked in the isolated local database; the live custom-domain editor and 390px mobile layout were verified without editing live product data.

Four-role implementation: owner, publisher, editor and viewer. Only owners manage members, restore revision history or request unpublishing. Viewers receive only the public snapshot, never working drafts, deleted drafts, revision metadata, publication jobs or participant details. Server-side guards enforce current roles; the UI refreshes role/session state periodically and on focus. Membership changes have their own audit history.

The local website consumer supports approved `removed` ID/SKU entries for recoverable owner unpublishing; these edits have not been deployed to the main domain. Main-site catalogue synchronization remains disabled. Before activation, deploy the updated consumer and bridge, complete the test-copy round trip, then enable publication. Existing SKU identity is preserved through unpublishing/republishing.
