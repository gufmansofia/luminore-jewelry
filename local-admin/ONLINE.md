# Online admin rollout

The separate online admin is published at https://admin.luminorejewelry.com/admin, with the original https://luminore-jewelry-admin.sgufman06.chatgpt.site/admin address also available. The online version uses owner-requested email-only entry, an invited-email allowlist, D1 records and R2 uploads. There is no password, OTP, email delivery or external sign-in provider. The owner explicitly accepted that anyone who knows an allowed email can enter as that member. Random HttpOnly cookie sessions are stored as hashes, checked against current membership, and invalidated on logout or revocation. The loopback-only Bun prototype remains separate and must never be exposed to the internet.

The website can consume only approved snapshots during its build by setting `ADMIN_CATALOGUE_URL=https://admin.luminorejewelry.com/catalogue-changes.json`. Leave the setting unset until catalogue migration, the Google Sheets bridge and a production deploy hook have been verified. Without it, the existing curated stock stays unchanged.

`build.ts` refreshes the snapshot before loading SEO modules or bundling the client. `mergeAdminProducts` preserves existing product IDs and SKUs, updates translated website fields and adds new published products. Failed downloads, invalid feeds or conflicting identity stop the new build, retaining the previous deployment. The build emits `.well-known/luminore-catalogue.json` so the admin can verify the actual published release instead of claiming completion merely after triggering a hook.

Multiple catalogue owners are supported by the primary `ADMIN_OWNER_EMAIL` plus optional comma-separated `ADMIN_OWNER_EMAILS` runtime secrets. Any owner can assign all four roles, appoint other owners, change their rights or revoke their access. The last active owner is protected. Emails are not hard-coded into website source.

Four-role implementation: owner, publisher, editor and viewer. Only owners manage members, restore revision history or request unpublishing. Viewers receive only the public snapshot, never working drafts, deleted drafts, revision metadata, publication jobs or participant details. Server-side guards enforce current roles; the UI refreshes role/session state periodically and on focus. Membership changes have their own audit history.
